# FileInput

FileInput lets users pick a file (or image) and upload it to your StartupJS backend. The `value` is a `fileId` pointing to a document in the `files` model, and `onChange` is called with the new `fileId` after a successful upload.

```jsx
import { FileInput } from "startupjs-ui";
```

## Basic usage

```jsx example
const [fileId, setFileId] = useState();
return <FileInput value={fileId} onChange={setFileId} />;
```

## Image picker

Set `image` to `true` to open an image picker instead of a document picker.

```jsx
const $avatarFileId = $();
const $file = useSub($.files[$avatarFileId.get() ?? "__DUMMY__"]);
return (
  <Div gap>
    <Span>Your avatar:</Span>
    {$avatarFileId.get() ? (
      <Avatar src={$file.getUrl() + "?" + $file.updatedAt.get()}>{name}</Avatar>
    ) : (
      <Span italic>No avatar uploaded</Span>
    )}
    <FileInput
      image
      value={$avatarFileId.get()}
      onChange={(fileId) => $avatarFileId.set(fileId)}
    />
  </Div>
);
```

**Note:** Appending `?` and the `updatedAt` timestamp to the URL is optional. It forces the browser to reload the image after it has been changed, instead of showing a cached version. This is useful for profile picture editors and similar use cases.

## Props

- **value** -- the current `fileId` (stored in the `files` model on the server)
- **onChange** -- called with the new `fileId` after a successful upload
- **image** -- when `true`, opens an image picker instead of a document picker
- **mimeTypes** -- a string or array of MIME types accepted by the picker
- **uploadImmediately** -- upload the selected file right after picking (default `true`)
- **beforeUpload** -- a hook called before the upload starts (can be async)
- **afterUpload** -- a hook called after the upload finishes (can be async)
- **render** -- a custom render function to replace the default Upload/Change/Delete buttons
- **style** -- custom styles for the component
- **ref** -- a ref object to access imperative methods (see below)

## Imperative methods

Pass a `ref` to access the following methods:

- **pickFile()** -- opens the native picker and optionally uploads the selected file
- **deleteFile()** -- deletes the currently selected file
- **uploadFile(asset, fileId?)** -- uploads a picked asset to the server and returns the new `fileId`

## Storage providers (plugin system)

FileInput uses a **modular plugin system** for storage backends. The core `@startupjs-ui/file-input` package is provider-agnostic — each storage backend is a separate package that you install and import explicitly.

### Available provider plugins

| Plugin package                             | Storage type | SDK dependency           |
| ------------------------------------------ | ------------ | ------------------------ |
| `@startupjs-ui/file-input-provider-sqlite` | `sqlite`     | _(built into startupjs)_ |
| `@startupjs-ui/file-input-provider-mongo`  | `mongo`      | `mongodb`                |
| `@startupjs-ui/file-input-provider-azure`  | `azureblob`  | `@azure/storage-blob`    |
| `@startupjs-ui/file-input-provider-s3`     | `s3`         | `@aws-sdk/client-s3`     |

### Setup

1. **Install** the provider plugin(s) you need:

```bash
# For MongoDB GridFS (default when MONGO_URL is configured):
yarn add @startupjs-ui/file-input-provider-mongo

# For SQLite (default for local dev without MongoDB):
yarn add @startupjs-ui/file-input-provider-sqlite

# For AWS S3:
yarn add @startupjs-ui/file-input-provider-s3

# For Azure Blob Storage:
yarn add @startupjs-ui/file-input-provider-azure
```

2. **Import** the plugin in your server entry point (e.g. `server/index.js`):

```js
// Simply importing the package registers the provider automatically
import "@startupjs-ui/file-input-provider-mongo";
import "@startupjs-ui/file-input-provider-sqlite";
```

3. **Configure** the default storage type (optional):

The system auto-detects which provider to use based on what is registered. You can force a specific one via the `DEFAULT_STORAGE_TYPE` environment variable:

```bash
DEFAULT_STORAGE_TYPE=mongo   # or sqlite, s3, azureblob
```

### Writing a custom provider plugin

You can create your own storage provider plugin. A plugin must:

1. Implement the provider interface (all functions are async):
   - `validateSupport()` — check that the backend is available
   - `getFileBlob(fileId, options)` — return file contents as Buffer
   - `getFileSize(fileId, options)` — return file size in bytes
   - `saveFileBlob(fileId, blob, options)` — save a Buffer to storage
   - `deleteFile(fileId, options)` — remove a file from storage

2. Register itself in the entry point:

```js
import { registerProvider } from "@startupjs-ui/file-input/providers/registry";
import * as provider from "./provider.js";

registerProvider("my-storage", provider);
```
