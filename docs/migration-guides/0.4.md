# Upgrade 0.3 to 0.4

- Change `startupjs-ui` and all `@startupjs-ui/*` dependencies in your `package.json` to `^0.4`
- Upgrade `startupjs` to the matching `0.64.0-alpha` version
- If you directly install `cssxjs` or any `@cssxjs/*` packages, upgrade them to `^0.4`
- Run `yarn` after the version bump

StartupJS UI 0.4 is a breaking styling release. The component library now uses CSSX 0.4 as its styling foundation instead of the old StartupJS UI theme/color/Stylus helper layer.

## Quick Migration Checklist

1. Upgrade StartupJS, CSSX, and StartupJS UI together.
2. Configure app theme overrides through `StartupjsProvider style`.
3. Replace old `.Button` global overrides with `Button` tag overrides.
4. Replace old theme palette/config usage with CSS variable overrides.
5. Replace old color and media helpers with CSSX primitives re-exported from `startupjs`.
6. Replace new `u` usage with `rem`, `var(--spacing)`, or `calc()`.
7. Review component docs for the parts and variables each component exposes.
8. Run `npx startupjs check`, `npx eslint .`, Storybook, and your app tests.

## CSS-First Theme Model

StartupJS UI now uses CSS variables as the theme API.

When `startupjs-ui` is installed, its StartupJS plugin injects the internal UI provider into `StartupjsProvider`. You configure UI themes at the app root:

```jsx
import { StartupjsProvider, css } from 'startupjs'

const appStyle = css`
  :root {
    --primary: oklch(0.55 0.2 250);
    --primary-foreground: white;
    --color-primary: var(--primary);
    --color-primary-foreground: var(--primary-foreground);
  }

  :root.dark {
    --primary: oklch(0.75 0.18 250);
  }
`

export default function Root () {
  return (
    <StartupjsProvider theme='auto' style={appStyle}>
      <App />
    </StartupjsProvider>
  )
}
```

StartupJS UI provides:

- Tailwind-compatible raw token variables from CSSX
- shadcn-style semantic variables from CSSX
- StartupJS UI component-specific variables

Your `StartupjsProvider style` is applied after those defaults, so your overrides win.

## Light And Dark Themes

`theme='auto'` is the default. It selects `:root.dark` when the OS color scheme is dark.

Use:

- `theme='default'` to force the default light values
- `theme='dark'` to force dark values
- `theme='light'` as an alias for default unless an explicit light theme exists
- `theme='<custom-name>'` to apply `:root.<custom-name>`

Theme-specific normal styles use CSSX theme media:

```css
@media (--theme-dark) {
  Button {
    box-shadow: none;
    border-color: var(--color-border);
  }
}
```

## Token Migration

Old StartupJS UI palette/config variables are not preserved as the new public API. Migrate to the new token model.
Direct `UiProvider` props `palette`, `colors`, and `componentColors` are no
longer supported. If they are passed at runtime, StartupJS UI reports an error
and ignores them. Move those overrides to `StartupjsProvider style` as CSSX
variables.

Prefer semantic shadcn-style variables:

```css
:root {
  --primary: oklch(0.55 0.2 250);
  --primary-foreground: white;
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);

  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --color-background: var(--background);
  --color-foreground: var(--foreground);
}
```

Use raw Tailwind palette variables only when there is no better semantic token:

```css
:root {
  --User-color-online: var(--color-green-500);
}
```

Component-specific variables use component-prefixed names:

```css
:root {
  --Button-radius: var(--radius-md);
  --Button-height-m: 2.5rem;
  --User-color-online: var(--color-success);
  --User-color-offline: var(--color-muted-foreground);
}
```

See the Styling guide and each component page for the supported parts and component variables.

## Global Component Overrides

Component overrides now use component tag selectors.

### Old

```css
.Button {
  background-color: red;
}

.Button:part(text) {
  color: green;
}
```

### New

```css
Button {
  background-color: var(--color-primary);
}

Button:part(text),
Button::part(text) {
  color: var(--color-primary-foreground);
}
```

The old class-like `.Button` convention was an implementation detail of the previous theme layer. Use `Button`, `Item`, `TextInput`, and other component tags for global overrides.

## Parts And Per-Instance Styles

`part` is the canonical external styling API.

- `part='root'` maps to the `style` prop
- `part='icon'` maps to `iconStyle`
- `part='text'` maps to `textStyle`
- other named parts map to `{partName}Style`

Use override mechanisms in this order:

1. CSS variables for broad theme changes
2. component tag selectors for component-level defaults
3. `Component:part(name)` or `Component::part(name)` for semantic subparts
4. per-instance `style` and `*Style` props as escape hatches

Example:

```css
:root {
  --Item-padding-y: 0.75rem;
}

Item:part(icon) {
  color: var(--color-muted-foreground);
}
```

Put component variable overrides in `:root`, `:root.dark`, or another provider theme block. Component tag selectors are for normal style declarations and `:part()` / `::part()` selectors are for semantic subparts.

## Button Variants

`Button` now follows the shadcn variant names:

- old `variant='flat'` -> `variant='default'`
- old `variant='outlined'` -> `variant='outline'`
- old `variant='text'` -> `variant='ghost'`

The old names still work during migration and print a one-time console warning. The default Button is now the shadcn-style primary filled button. Use `variant='outline'`, `variant='secondary'`, `variant='ghost'`, or `variant='link'` for quieter actions.

## Replacing Old Style Helpers

Move style helper imports to CSSX primitives re-exported from `startupjs`.

```js
import {
  useCssVariable,
  useCssVariableRaw,
  useCssColor,
  getCssColor,
  useMedia,
  u
} from 'startupjs'
```

Migration notes:

- old `useMedia` -> `useMedia()` from `startupjs`
- old color token helpers -> CSS `var()` / `color-mix()` or `useCssColor()`
- old `colorToRGBA` mixing -> `useCssColor('primary', 0.15)` or CSS `color-mix()`
- JS `u()` -> deprecated `u()` from `startupjs` only as a migration fallback
- CSS `u` units -> `rem`, `var(--spacing)`, or `calc()`

Prefer CSS for styling and use JS hooks only when a non-CSS prop needs a resolved value.

## `@startupjs-ui/core`

`@startupjs-ui/core` is no longer a style/theme helper package.

It remains only for small shared non-style types, currently `UIRole`. `startupjs-ui` re-exports the `UIRole` type for wrappers around UI components.

Remove imports of style helpers from `@startupjs-ui/core`.

## Stylus And Separate Style Files

StartupJS UI internals moved away from component `.cssx.styl` / `.cssx.css` files. Component styles now live next to component markup in CSSX templates.

Your app can still use separate `.cssx.css` and `.cssx.styl` files when useful, but new component code should prefer:

- `style` blocks inside `pug` templates for static local styles
- local `css` templates when JS interpolation is needed
- plain CSS variables and standard CSS functions instead of Stylus helpers

## Spacing Migration

New StartupJS UI styles use `rem`, `var(--spacing)`, and Tailwind/shadcn token scales.

`1u` equals `0.5rem`, or 8px with the default 16px rem base.

```css
/* old */
padding: 2u;

/* new */
padding: 1rem;
padding: calc(var(--spacing) * 4);
```

## Custom Media And Breakpoints

Use CSSX `@custom-media` and `useMedia()`:

```css
:root {
  --tablet: 48rem;
  --desktop: 64rem;
}

@custom-media --breakpoint-tablet (width >= var(--tablet));
@custom-media --breakpoint-desktop (width >= var(--desktop));
```

```js
import { useMedia } from 'startupjs'

function Sidebar () {
  const media = useMedia()
  return media.desktop ? <DesktopSidebar /> : <MobileSidebar />
}
```
