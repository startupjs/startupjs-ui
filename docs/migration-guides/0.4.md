# Upgrade 0.3 to 0.4

- Change `startupjs-ui` and all `@startupjs-ui/*` dependencies in your `package.json` to `^0.4`
- Upgrade `startupjs` to the matching `0.64.0-alpha` version
- If you directly install `cssxjs` or any `@cssxjs/*` packages, upgrade them to `^0.4`
- Run `yarn` after the version bump

StartupJS UI 0.4 is a breaking styling release. The component library now uses CSSX 0.4 as its styling foundation instead of the old StartupJS UI theme/color/Stylus helper layer.

## What Usually Keeps Working

If your app only imports and renders StartupJS UI components, most component
props are intended to keep working. The visual theme changes, but regular
component usage such as `style`, `*Style`, `styleName`, `part`, form props,
input props, and layout props should not require a rewrite.
Non-theme provider options such as `routerPortal` keep their existing behavior.

Most migration work is needed when your app:

- customized the old global UI theme with `palette`, `colors`, or `componentColors`
- imported style/theme helpers from `@startupjs-ui/core`
- used old `.Button` / `.Item` global overrides
- depended on old CSS variable names, Stylus `$UI`, `u`, or old palette tokens
- depended on the old Button default visual style or old Button variant names

## Quick Migration Checklist

1. Upgrade StartupJS, CSSX, and StartupJS UI together.
2. Configure app theme overrides through `StartupjsProvider style`.
3. Replace old `.Button` global overrides with `Button` tag overrides.
4. Replace old theme palette/config usage with CSS variable overrides.
5. Replace old color and media helpers with CSSX primitives re-exported from `startupjs`.
6. Replace old `u` usage with `rem`, `var(--spacing)`, or `calc()`.
7. If you enable dark mode, set `StartupjsProvider theme='auto'` and wire Expo Router / React Navigation colors to CSSX.
8. Review component docs for the parts and variables each component exposes.
9. Run `npx startupjs check`, `npx eslint .`, Storybook, and your app tests.

## CSS-First Theme Model

StartupJS UI now uses CSS variables as the theme API.

When `startupjs-ui` is installed, its StartupJS plugin injects the internal UI provider into `StartupjsProvider`. You configure UI themes at the app root:

```jsx
import { StartupjsProvider, css } from 'startupjs'

const appStyle = css`
  :root {
    --primary: oklch(0.55 0.2 250);
    --primary-foreground: white;
    --color-primary: var(--primary);
    --color-primary-foreground: var(--primary-foreground);
  }

  :root.dark {
    --primary: oklch(0.75 0.18 250);
  }
`

export default function Root () {
  return (
    <StartupjsProvider style={appStyle}>
      <App />
    </StartupjsProvider>
  )
}
```

StartupJS UI provides:

- Tailwind-compatible raw token variables from CSSX
- shadcn-style semantic variables from CSSX
- StartupJS UI component-specific variables

Your `StartupjsProvider style` is applied after those defaults, so your overrides win.

## Light And Dark Themes

When no saved user preference exists, the root provider starts with the default
light values from `:root`. This avoids a common Expo Router / React Navigation
mismatch where StartupJS UI components render with dark CSSX tokens while the
native navigation shell stays white.

Use `theme='auto'` when your app is ready to follow the OS color scheme. At the
root, `theme='auto'` is an initial/system preference; a saved preference from
`useTheme()` or the `DarkMode` button takes priority after the user chooses
one.

Use:

- no `theme` prop for the default root preference with saved user preference support
- `theme='auto'` to select `:root.dark` on dark systems when a dark theme exists
- `theme='default'` to force the default light values
- `theme='dark'` to force dark values
- `theme='light'` as an alias for default unless an explicit light theme exists
- `theme='<custom-name>'` to apply `:root.<custom-name>`

Use `DarkMode` from `startupjs-ui` for a ready-made theme toggle, or
`useTheme()` from `startupjs` when you need a custom control:

```jsx
import { useTheme } from 'startupjs'
import { Button } from 'startupjs-ui'

function ThemeSwitch () {
  const [theme, setTheme] = useTheme()
  return (
    <Button
      variant='outline'
      onPress={() => setTheme(theme === 'dark' ? 'default' : 'dark')}
    >
      Toggle theme
    </Button>
  )
}
```

Theme-specific normal styles use CSSX theme media:

```css
@media (--theme-dark) {
  Button {
    box-shadow: none;
    border-color: var(--color-border);
  }
}
```

### Expo Router / React Navigation recipe

If you opt into dark mode, also wire Expo Router / React Navigation colors to
CSSX. Otherwise the UI components can switch to dark mode while the navigation
header, tab bar, or scene background remains light.

Install CSSX theme persistence for native apps:

```sh
npx expo install @react-native-async-storage/async-storage
```

Root layout:

```tsx
// app/_layout.tsx
import React from 'react'
import { Slot } from 'expo-router'
import { StartupjsProvider } from 'startupjs'

export default function RootLayout () {
  return (
    <StartupjsProvider theme='auto'>
      <Slot />
    </StartupjsProvider>
  )
}
```

Stack layout with a header toggle:

```tsx
// app/(app)/_layout.tsx
import React from 'react'
import { Stack } from 'expo-router'
import { observer, useCssColor } from 'startupjs'
import { DarkMode } from 'startupjs-ui'

export default observer(function AppLayout () {
  const backgroundColor = useCssColor('background')
  const foregroundColor = useCssColor('foreground')

  return (
    <Stack
      screenOptions={{
        contentStyle: { backgroundColor },
        headerStyle: { backgroundColor },
        headerTintColor: foregroundColor,
        headerTitleStyle: { color: foregroundColor },
        headerShadowVisible: false,
        headerRight: () => <DarkMode variant='ghost' size='s' />
      }}
    />
  )
})
```

Tabs layout:

```tsx
// app/(tabs)/_layout.tsx
import React from 'react'
import { Tabs } from 'expo-router'
import { observer, useCssColor } from 'startupjs'
import { DarkMode } from 'startupjs-ui'

export default observer(function TabsLayout () {
  const backgroundColor = useCssColor('background')
  const foregroundColor = useCssColor('foreground')
  const borderColor = useCssColor('border')
  const primaryColor = useCssColor('primary')
  const mutedForegroundColor = useCssColor('muted-foreground')
  const activeBackgroundColor = useCssColor('primary', 0.08)

  return (
    <Tabs
      screenOptions={{
        sceneStyle: { backgroundColor },
        headerStyle: { backgroundColor },
        headerTintColor: foregroundColor,
        headerTitleStyle: { color: foregroundColor },
        headerShadowVisible: false,
        headerRight: () => <DarkMode variant='ghost' size='s' />,
        tabBarStyle: { backgroundColor, borderColor },
        tabBarActiveTintColor: primaryColor,
        tabBarActiveBackgroundColor: activeBackgroundColor,
        tabBarInactiveTintColor: mutedForegroundColor
      }}
    />
  )
})
```

If a screen already has header actions, put `DarkMode` next to them:

```tsx
import { Button, DarkMode, Div } from 'startupjs-ui'

<Stack.Screen
  options={{
    headerRight: () => (
      <Div row vAlign='center' gap={1}>
        <Button variant='ghost'>Edit</Button>
        <DarkMode variant='ghost' size='s' />
      </Div>
    )
  }}
/>
```

## Token Migration

Old StartupJS UI palette/config variables are not preserved as the new public API. Migrate to the new token model.
Direct `UiProvider` props `palette`, `colors`, and `componentColors` are no
longer supported. If they are passed at runtime, StartupJS UI reports an error
and ignores them. Move those overrides to `StartupjsProvider style` as CSSX
variables.

### Old

```jsx
import { StartupjsProvider } from 'startupjs'
import styleOverrides from './style.cssx.styl'

const palette = {
  primary: '#1677ff'
}
const colors = {
  primary: 'primary'
}
const componentColors = {
  Button: {
    primary: 'primary'
  }
}

export default function Root () {
  return (
    <StartupjsProvider
      style={styleOverrides}
      palette={palette}
      colors={colors}
      componentColors={componentColors}
    >
      <App />
    </StartupjsProvider>
  )
}
```

### New

```jsx
import { StartupjsProvider, css } from 'startupjs'

const appStyle = css`
  :root {
    --primary: #1677ff;
    --primary-foreground: white;
    --color-primary: var(--primary);
    --color-primary-foreground: var(--primary-foreground);
  }
`

export default function Root () {
  return (
    <StartupjsProvider style={appStyle}>
      <App />
    </StartupjsProvider>
  )
}
```

Prefer semantic shadcn-style variables:

```css
:root {
  --primary: oklch(0.55 0.2 250);
  --primary-foreground: white;
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);

  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --color-background: var(--background);
  --color-foreground: var(--foreground);
}
```

Use raw Tailwind palette variables only when there is no better semantic token:

```css
:root {
  --User-color-online: var(--color-green-500);
}
```

Component-specific variables use component-prefixed names:

```css
:root {
  --Button-radius: var(--radius-md);
  --Button-height-m: 2.5rem;
  --User-color-online: var(--color-success);
  --User-color-offline: var(--color-muted-foreground);
}
```

Variable overrides must live in provider root blocks such as `:root`,
`:root.dark`, or another `:root.<theme>`. Component selectors are for normal
style declarations and do not define provider-scoped variables.

See the Styling guide and each component page for the supported parts and
component variables. For complete token references, use:

- CSSX Tailwind tokens: `cssxjs/themes/tailwind`
- CSSX shadcn semantic tokens: `cssxjs/themes/shadcn`
- StartupJS UI component tokens: `packages/startupjs-ui/startupjsUiTheme.js`

## Global Component Overrides

Component overrides now use component tag selectors.

### Old

```css
.Button {
  background-color: red;
}

.Button:part(text) {
  color: green;
}
```

### New

```css
Button {
  background-color: var(--color-primary);
}

Button:part(text),
Button::part(text) {
  color: var(--color-primary-foreground);
}
```

The old class-like `.Button` convention was an implementation detail of the previous theme layer. Use `Button`, `Item`, `TextInput`, and other component tags for global overrides.

## Parts And Per-Instance Styles

`part` is the canonical external styling API.

- `part='root'` maps to the `style` prop
- `part='icon'` maps to `iconStyle`
- `part='text'` maps to `textStyle`
- other named parts map to `{partName}Style`

Use override mechanisms in this order:

1. CSS variables for broad theme changes
2. component tag selectors for component-level defaults
3. `Component:part(name)` or `Component::part(name)` for semantic subparts
4. per-instance `style` and `*Style` props as escape hatches

Example:

```css
:root {
  --Item-padding-y: 0.75rem;
}

Item:part(icon) {
  color: var(--color-muted-foreground);
}
```

Put component variable overrides in `:root`, `:root.dark`, or another provider theme block. Component tag selectors are for normal style declarations and `:part()` / `::part()` selectors are for semantic subparts.

## Button Variants

`Button` now follows the shadcn variant names:

- old `variant='flat'` -> `variant='default'`
- old `variant='outlined'` -> `variant='outline'`
- old `variant='text'` -> `variant='ghost'`

The old names still work during migration and print a one-time console warning. The default Button is now the shadcn-style primary filled button. Use `variant='outline'`, `variant='secondary'`, `variant='ghost'`, or `variant='link'` for quieter actions.

## Replacing Old Style Helpers

Move style helper imports to CSSX primitives re-exported from `startupjs`.

```js
import {
  useCssVariable,
  useCssVariableRaw,
  useCssColor,
  getCssColor,
  useMedia,
  u
} from 'startupjs'
```

Migration notes:

| Old API / pattern | New API / pattern |
| --- | --- |
| `useMedia` from `@startupjs-ui/core` | `useMedia()` from `startupjs` |
| old color token helpers | CSS `var()` / `color-mix()` or `useCssColor()` |
| `colorToRGBA(color, opacity)` | `useCssColor('primary', opacity)` or CSS `color-mix()` |
| `Colors`, `Palette`, `generateColors`, `CssVariables` | CSS variables in `StartupjsProvider style` |
| `themed` from StartupJS UI internals | `themed()` from `startupjs` |
| JS `u()` | deprecated `u()` from `startupjs` only as a migration fallback |
| CSS `u` units | `rem`, `var(--spacing)`, or `calc()` |

Prefer CSS for styling and use JS hooks only when a non-CSS prop needs a resolved value.

## `@startupjs-ui/core`

`@startupjs-ui/core` is no longer a style/theme helper package.

It remains only for small shared non-style types, currently `UIRole`. `startupjs-ui` re-exports the `UIRole` type for wrappers around UI components.

Remove imports of style helpers from `@startupjs-ui/core`.

## Stylus And Separate Style Files

StartupJS UI internals moved away from component `.cssx.styl` / `.cssx.css` files. Component styles now live next to component markup in CSSX templates.

Your app can still use separate `.cssx.css` and `.cssx.styl` files when useful, but new component code should prefer:

- `style` blocks inside `pug` templates for static local styles
- local `css` templates when JS interpolation is needed
- plain CSS variables and standard CSS functions instead of Stylus helpers

You do not need to rewrite every existing `style(lang='styl')` block to CSS.
Stylus remains supported. The migration is to stop relying on the old
StartupJS UI Stylus helper globals and to write CSSX-friendly declarations
inside Stylus.

### Migrating app Stylus helpers

Replace old StartupJS UI helper syntax with CSSX variables and standard CSS
features:

| Old Stylus pattern | New CSSX/Stylus pattern |
| --- | --- |
| `$UI...` theme values | `var(--color-*)`, `var(--text-*)`, `var(--radius-*)`, component variables, or app variables in `StartupjsProvider style` |
| `+tablet()`, `+desktop()`, `+wide()` | `@media (--breakpoint-tablet)`, `@media (--breakpoint-desktop)`, `@media (--breakpoint-wide)` |
| `font(h1)` ... `font(h6)` | `font-size var(--Span-h1-font-size)` ... `var(--Span-h6-font-size)` plus matching `line-height` variables |
| old color opacity helpers | CSS `color-mix()` or JS `useCssColor('primary', opacity)` when a native prop needs a JS value |
| `1u`, `2u`, etc. | `0.5rem`, `1rem`, `calc(var(--spacing) * 2)`, `calc(var(--spacing) * 4)` |

Example:

```pug
View.root

style(lang='styl').
  .root
    font(h6)
    color $UI.colors.textDescription
    margin-bottom 1u

    +tablet()
      margin-bottom 2u
```

becomes:

```pug
View.root

style(lang='styl').
  .root
    font-size var(--Span-h6-font-size)
    line-height var(--Span-h6-line-height)
    color var(--color-text-description)
    margin-bottom 0.5rem

    @media (--breakpoint-tablet)
      margin-bottom 1rem
```

If there is no direct replacement for an old `$UI` value, define an app-level
semantic variable instead of hard-coding the value where it is used:

```jsx
import { StartupjsProvider, css } from 'startupjs'

const appStyle = css`
  :root {
    --Profile-avatar-size: 4rem;
    --Profile-status-online: var(--color-success);
  }
`

export default function Root () {
  return (
    <StartupjsProvider style={appStyle}>
      <App />
    </StartupjsProvider>
  )
}
```

Then use those variables from Stylus:

```stylus
.avatar
  width var(--Profile-avatar-size)
  height var(--Profile-avatar-size)

.online
  color var(--Profile-status-online)
```

### Where to find replacement variables

Use the most semantic token that fits before falling back to raw palette
values:

1. Component docs styling tables: supported `part` names and `--Component-*`
   variables for that component.
2. StartupJS UI component/theme variables:
   `startupjs-ui/startupjsUiTheme.js`.
3. shadcn semantic tokens from CSSX: `cssxjs/themes/shadcn`, including
   `--background`, `--foreground`, `--primary`, `--muted-foreground`,
   `--border`, and their `--color-*` aliases.
4. Tailwind raw tokens from CSSX: `cssxjs/themes/tailwind`, including
   `--color-blue-500`, `--text-sm`, `--radius-md`, `--shadow-sm`,
   `--spacing`, and breakpoint variables.

Prefer semantic variables such as `--color-primary`,
`--color-muted-foreground`, or `--Button-height-m` in app styles. Use raw
palette variables such as `--color-blue-500` only when no semantic token fits.

## Spacing Migration

New StartupJS UI styles use `rem`, `var(--spacing)`, and Tailwind/shadcn token scales.

`1u` equals `0.5rem`, or 8px with the default 16px rem base.

```css
/* old */
padding: 2u;

/* new */
padding: 1rem;
padding: calc(var(--spacing) * 4);
```

## Custom Media And Breakpoints

Use CSSX custom media aliases and `useMedia()`.

The default aliases are already available:

- `--breakpoint-mobile`
- `--breakpoint-tablet`
- `--breakpoint-desktop`
- `--breakpoint-wide`

Most app migrations only need to replace old Stylus breakpoint mixins:

```stylus
// old
+tablet()
  display flex

// new
@media (--breakpoint-tablet)
  display flex
```

Define your own aliases only when the app needs custom breakpoint names:

```css
:root {
  --tablet: 48rem;
  --desktop: 64rem;
}

@custom-media --breakpoint-tablet (width >= var(--tablet));
@custom-media --breakpoint-desktop (width >= var(--desktop));
```

```js
import { useMedia } from 'startupjs'

function Sidebar () {
  const media = useMedia()
  return media.desktop ? <DesktopSidebar /> : <MobileSidebar />
}
```
