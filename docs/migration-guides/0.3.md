# Upgrade 0.2 to 0.3

- Change `startupjs-ui` and all `@startupjs-ui/*` dependencies in your `package.json` to `^0.3`
- Run `yarn` after the version bump

Version `0.3` is mostly source-compatible with `0.2`, but it is intentionally published as a breaking version because accessibility and E2E testability were substantially expanded across the component library.

## Quick Migration Checklist

1. Replace legacy `accessibility*` props in app code with `role` and `aria-*` props.
2. Replace `nativeID` with `id`.
3. Use `testID`, not `testId` or `data-testid`.
4. Prefer Playwright semantic locators before test IDs.
5. Review custom render functions and custom input wrappers that need to forward `testID`, `id`, `role`, or `aria-*`.

## Accessibility API

StartupJS UI now targets the current React Native and React Native Web accessibility API:

```js
Button(
  role='button'
  aria-label='Save profile'
  testID='save-profile'
)
```

Avoid the legacy React Native props in StartupJS UI component APIs:

```js
// old
Button(accessibilityRole='button' accessibilityLabel='Save profile')

// new
Button(role='button' aria-label='Save profile')
```

If a legacy `accessibility*` prop is passed through a transparent low-level wrapper such as `Div` or `Span`, React Native may still receive it. StartupJS UI internals and documented APIs use only `role` and `aria-*`.

## IDs

Use `id` instead of `nativeID`.

```js
Div(id='settings-panel')
TextInput(id='email-input')
```

This is the API supported by current React Native and React Native Web, and it gives web E2E tests stable element relationships.

## Test IDs

Use only `testID`.

```js
Button(testID='submit-profile')
```

React Native Web renders `testID` as `data-testid`, so Playwright can still use:

```js
await page.getByTestId('submit-profile').click()
```

Do not pass `testId` or `data-testid` to StartupJS UI components.

## Prefer Semantic Locators

The recommended Playwright locator order is:

```js
await page.getByRole('button', { name: 'Save profile' }).click()
await page.getByLabel('Email').fill('ada@example.com')
await page.getByText('Profile updated').isVisible()
await page.getByTestId('fallback-action').click()
```

Use `testID` when no stable accessible role, label, or text exists.

## Input Labels

Wrapped inputs now expose better label relationships. In most cases, you should not manually pass `aria-label` when the component already has a `label`.

```js
Input(
  type='text'
  label='Email'
  $value=$user.email
)
```

Playwright should be able to use:

```js
await page.getByLabel('Email').fill('ada@example.com')
```

This applies across the high-level `Input` types such as text, number, password, select, multi-select, checkbox, radio, range, color, date/time, file, object, and array inputs.

## Select-Like Components

Select-like components expose web-friendly combobox/listbox/option semantics where applicable. Prefer role locators for the trigger and options:

```js
await page.getByRole('combobox', { name: 'Role' }).click()
await page.getByRole('option', { name: 'Admin' }).click()
```

This affects components such as `Select`, `MultiSelect`, `Dropdown`, and `AutoSuggest`.

## Wrapper Props

`ArrayInput`, `ObjectInput`, and `Form` now support wrapper-level `testID`, `id`, `role`, and the main `aria-*` props.

```js
Form(
  testID='profile-form'
  role='form'
  aria-label='Profile'
  $value=$profile
  fields=fields
)
```

If you provide a custom `_renderWrapper`, make sure it forwards the wrapper props it receives:

```js
function renderWrapper ({ style, testID, id, role, ...ariaProps }, children) {
  return pug`
    Card(
      style=style
      testID=testID
      id=id
      role=role
      ...ariaProps
    )= children
  `
}
```

## Custom Render Functions

Some components allow custom render functions for their content. If you replace the default rendered element, you are responsible for preserving useful semantics and test hooks.

For example, if a render function receives `testID`, `id`, `role`, or `aria-*`, forward those props to the main interactive or container element that users and tests should target.

## Practical Upgrade Pass

Search your app for these patterns:

```bash
rg "accessibility[A-Z]|nativeID|testId|data-testid"
```

Then migrate each match:

- `accessibilityLabel` -> `aria-label`
- `accessibilityRole` -> `role`
- `accessibilityState={{ disabled: true }}` -> `aria-disabled`
- `accessibilityState={{ expanded: value }}` -> `aria-expanded`
- `accessibilityState={{ selected: value }}` -> `aria-selected`
- `accessibilityState={{ checked: value }}` -> `aria-checked`
- `nativeID` -> `id`
- `testId` / `data-testid` -> `testID`

After updating app code, run the E2E suite and prefer replacing brittle selectors with semantic locators as you touch tests.
